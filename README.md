# Global E-Commerce SQL Chatbot

A conversational analytics chatbot over the supplied multi-table e-commerce dataset.

## Architecture

`User -> FastAPI -> LLM intent extraction -> validated JSON -> SQL query builder -> SQLite -> deterministic answer`

The chatbot **does not build a flat customer table** and does not let the LLM execute arbitrary SQL. Every analytical query is generated by approved SQL templates over the source tables:

- `customers`
- `transactions`
- `sessions`
- `marketing_campaigns`
- `geo_data`
- `customer_targets` (from train.csv)

## Features

- Multi-table SQL joins / CTEs
- Country normalization (`usa`, `U.S.`, etc. -> `USA`)
- Spend, AOV, transaction count, session metrics
- Rankings by country, region, tier, traffic source, payment method, device, campaign type, geo tier
- Counts and averages
- Customer-level lookups
- Date filters
- Top-N questions
- Deterministic formatting and SQL safety validation
- Gemini API support (structured JSON)
- Ollama support (local)
- Rule-based fallback for common questions when no LLM key is configured
- Simple web chat UI

## 1. Install

```bash
python -m venv .venv
# Windows
.venv\\Scripts\\activate
# macOS/Linux
source .venv/bin/activate
pip install -r requirements.txt
```

## 2. Build the SQL database

Put the supplied CSVs under `data/` (they are already included in this project package if you received the generated bundle), then:

```bash
python scripts/build_database.py
```

This creates `ecommerce.db` locally.

## 3. Configure an LLM (optional but recommended)

### Gemini

Set:

```env
LLM_PROVIDER=gemini
GEMINI_API_KEY=your_key
GEMINI_MODEL=gemini-2.5-flash
```

### Ollama

Install Ollama and pull a model such as `gpt-oss:20b`, then:

```env
LLM_PROVIDER=ollama
OLLAMA_MODEL=gpt-oss:20b
OLLAMA_BASE_URL=http://localhost:11434
```

### No LLM

Leave `LLM_PROVIDER=auto`. The app will use Gemini if a key exists, otherwise Ollama if available, otherwise the built-in rule parser.

## 4. Run

```bash
uvicorn app.main:app --reload
```

Open `http://127.0.0.1:8000`.

For production, run without `--reload` behind a reverse proxy, set a real
`DB_PATH`, keep `EXPOSE_SQL=false`, and configure process-level access logs,
TLS, authentication, and rate limiting at the proxy or platform layer.

## Example questions

- Which country has the highest total spend?
- What is the average order value by country?
- Show the top 5 countries by transaction count.
- Which customer tier has the highest average order value?
- How many customers are from USA?
- What is customer 8745's total spend?
- Which traffic source generates the most orders?
- Which device type has the highest average session duration?
- What is the average income by region tier?
- Which campaign type has the largest budget?
- How many transactions happened after 2024-01-01?

## Important data limitation

The supplied files contain raw customer/transaction/session/campaign/geo data plus `train.csv` targets. They do **not** contain the previously engineered dashboard fields such as saved RFM labels, K-Means cluster labels, or a saved purchase-probability prediction column. This chatbot therefore computes supported analytics directly from the source tables. If you later provide the model prediction output, add it as another table and a query template rather than flattening everything into one row.
